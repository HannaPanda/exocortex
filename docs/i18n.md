# Interface languages

eXocortex speaks `de`, `en`, `es`, `fr`, `it`, `nl`, `pl` and `pt-BR`. German
is the source; every other catalogue is translated from it. The decision and
its reasons are [ADR-062](adr/ADR-062-the-interface-language-belongs-to-the-person.md);
this page is the recipe.

## Where things are

| Path                                         | What it is                                                                |
| -------------------------------------------- | ------------------------------------------------------------------------- |
| `packages/contracts/src/locale.ts`           | `SUPPORTED_LOCALES`, the endonyms, the preference DTOs                    |
| `packages/i18n/src/messages/<locale>/*.json` | the catalogues, one file per namespace                                    |
| `packages/i18n/src/catalog.generated.ts`     | static imports of every file, generated, never edited                     |
| `packages/i18n/translation-state.json`       | per locale and key: hash of the German source, hash of the machine output |
| `packages/i18n/glossary.json`                | fixed terms per language, names never translated, the register            |
| `packages/i18n/context/<namespace>.md`       | two sentences on where a namespace's strings appear, sent to the model    |
| `apps/web/src/i18n/request.ts`               | resolves the locale per request, hands the web namespaces to the provider |
| `apps/web/src/components/locale-sync.tsx`    | moves the cookie to the account's choice once the session arrived         |
| `scripts/i18n/translate.mjs`                 | the translation tool                                                      |
| `scripts/check-i18n.mjs`                     | the catalogue gate                                                        |
| `scripts/check-i18n-literals.mjs`            | the ratchet on inline German, with `scripts/i18n-literals-baseline.json`  |

## A new string

1. Add it to the German namespace file that matches the screen, for example
   `packages/i18n/src/messages/de/settings.json`. Keys are English and
   describe the role (`saveFailed`), not the words.
2. Read it with `useTranslations('<namespace>.<group>')` and `t('<key>')`.
   Arguments are ICU: `{count, plural, one {# Seite} other {# Seiten}}`,
   `{name}`, `<link>{title}</link>` with `t.rich`.
3. `pnpm i18n:translate --all`. It translates only the new key, checks the
   answer, writes all seven files and regenerates the catalogue.
4. `pnpm --filter @exocortex/i18n build` so the web app's types see the key,
   then `node scripts/check-i18n.mjs` and, if a file lost inline German,
   `node scripts/check-i18n-literals.mjs --update`.

Changing a German string is the same, from step 3: the old machine
translations are stale and are redone.

## Text that is not read by a component

- **API errors.** A code becomes a sentence in `errors.codes`, and
  `messageForCode` in `apps/web/src/lib/api/error-messages.ts` is the only
  place that looks one up. `ErrorMessages` in the client providers installs the
  translator of the active language, and `ApiError.message` resolves when it is
  read, so an error still on screen follows a change of language. A new code in
  `packages/contracts` without a German sentence is a compile error there.
- **`packages/ui`.** The shared components read the `ui` namespace through
  `use-intl` (the library under next-intl, one instance), never through
  next-intl itself, so the design system does not depend on Next.js. A prop
  such as `label` or `placeholder` still overrides the default.
- **A pure helper** returns a key, or takes `t`, and never a sentence
  (`signInErrorKey` in `apps/web/src/lib/auth/sign-in-error.ts`).

## Correcting a translation by hand

Edit the target file. The tool notices the text is no longer what it wrote
and stops touching it. When the German of that key changes later, the tool
reports it instead of overwriting it, and the gate is red until one of:

- you correct the translation and confirm it:
  `pnpm i18n:translate --accept pl:settings.language.intro`
- you let the tool redo it: `pnpm i18n:translate --locale pl --overwrite-manual settings.language.intro`

## A new language

1. Add the tag to `SUPPORTED_LOCALES` and its endonym to `LOCALE_ENDONYMS`
   in `packages/contracts/src/locale.ts`.
2. Add its register to `packages/i18n/glossary.json` and, where the glossary
   has terms, the translation of each.
3. Add its English name to `LANGUAGE_NAMES` in `scripts/i18n/translate.mjs`.
4. `pnpm i18n:translate --locale <tag>`.

Nothing else changes: the settings page lists the new language, negotiation
finds it, the gate checks it.

## Formatting and sorting

Dates, numbers and relative times come from `useFormatter()` in the browser
and `createFormatter` from `use-intl/core` on the server, both with the
active locale. A new `'de-DE'` in a formatter is a defect.

Order that a person reads alphabetically (titles in a list) uses
`Intl.Collator(locale)`. Order that is technical (`orderKey`, ISO timestamps,
ids, slugs, anything hashed or serialised) compares by code unit and never
calls `localeCompare`, which silently depends on the process's locale.

## What is not translated

User content of every kind, the model-facing text (system prompts, MCP tool
descriptions, `instructions.ts`), logs and error codes. The styleguide's demo
sentences under `/design-system` stay German; the components they show are
translated.

## The model

`scripts/i18n/translate.mjs` pins `google/gemini-3.8-flash`. It was chosen on
2026-09-25 against a sample of 51 interface strings (36 error messages, 10
labels and explanations, 5 ICU messages with plural, select, date and a
rich-text tag), translated into Polish and French by four candidates:

| Model                          | Result                                                                                                      |
| ------------------------------ | ----------------------------------------------------------------------------------------------------------- |
| `google/gemini-3.8-flash`      | all checks passed; every Polish plural category right, including `other`; gender-neutral phrasing; chosen   |
| `deepseek/deepseek-v4.1-flash` | all checks passed and cheapest; gendered forms where the reader is unknown ("Otrzymałeś")                   |
| `anthropic/claude-sonnet-5`    | all checks passed; Polish `other` in the `many` form, letter-style capitals ("Ci"); several times the price |
| `mistralai/mistral-large-2512` | rate-limited upstream, no result                                                                            |

The sample also changed the prompt: every model wrote French apostrophes as
`''` when told that ICU needs doubled apostrophes, so the tool now asks for
the typographic apostrophe (’), which needs no escaping. Changing the model is
a commit with a new sample, not an environment variable left set by accident;
`I18N_TRANSLATE_MODEL` exists for trying one.
