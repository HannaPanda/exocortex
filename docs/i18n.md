# Interface languages

eXocortex speaks `de`, `en`, `es`, `fr`, `it`, `nl`, `pl` and `pt-BR`. German
is the source; every other catalogue is translated from it. The decision and
its reasons are [ADR-062](adr/ADR-062-the-interface-language-belongs-to-the-person.md);
this page is the recipe.

## Where things are

| Path                                         | What it is                                                                |
| -------------------------------------------- | ------------------------------------------------------------------------- |
| `packages/contracts/src/locale.ts`           | `SUPPORTED_LOCALES`, the endonyms, the preference DTOs                    |
| `packages/i18n/src/messages/<locale>/*.json` | the catalogues, one file per namespace                                    |
| `packages/i18n/src/catalog.generated.ts`     | static imports of every file, generated, never edited                     |
| `packages/i18n/translation-state.json`       | per locale and key: hash of the German source, hash of the machine output |
| `packages/i18n/glossary.json`                | fixed terms per language, names never translated, the register            |
| `packages/i18n/context/<namespace>.md`       | two sentences on where a namespace's strings appear, sent to the model    |
| `apps/web/src/i18n/request.ts`               | resolves the locale per request, hands the web namespaces to the provider |
| `apps/web/src/components/locale-sync.tsx`    | moves the cookie to the account's choice once the session arrived         |
| `scripts/i18n/translate.mjs`                 | the translation tool                                                      |
| `scripts/check-i18n.mjs`                     | the catalogue gate                                                        |
| `scripts/check-i18n-literals.mjs`            | the ratchet on inline German, with `scripts/i18n-literals-baseline.json`  |

## A new string

1. Add it to the German namespace file that matches the screen, for example
   `packages/i18n/src/messages/de/settings.json`. Keys are English and
   describe the role (`saveFailed`), not the words.
2. Read it with `useTranslations('<namespace>.<group>')` and `t('<key>')`.
   Arguments are ICU: `{count, plural, one {# Seite} other {# Seiten}}`,
   `{name}`, `<link>{title}</link>` with `t.rich`.
3. `pnpm i18n:translate --all`. It translates only the new key, checks the
   answer, writes all seven files and regenerates the catalogue.
4. `pnpm --filter @exocortex/i18n build` so the web app's types see the key,
   then `node scripts/check-i18n.mjs` and, if a file lost inline German,
   `node scripts/check-i18n-literals.mjs --update`.

Changing a German string is the same, from step 3: the old machine
translations are stale and are redone.

## Text that is not read by a component

- **API errors.** A code becomes a sentence in `errors.codes`, and
  `messageForCode` in `apps/web/src/lib/api/error-messages.ts` is the only
  place that looks one up. `ErrorMessages` in the client providers installs the
  translator of the active language, and `ApiError.message` resolves when it is
  read, so an error still on screen follows a change of language. A new code in
  `packages/contracts` without a German sentence is a compile error there.
- **`packages/ui`.** The shared components read the `ui` namespace through
  `use-intl` (the library under next-intl, one instance), never through
  next-intl itself, so the design system does not depend on Next.js. A prop
  such as `label` or `placeholder` still overrides the default.
- **A pure helper** returns a key, or takes `t`, and never a sentence
  (`signInErrorKey` in `apps/web/src/lib/auth/sign-in-error.ts`).
- **Mail** (`mail`) is written in the reader's language: `renderMail(message,
locale)` and `Mailer.send({ to, message, locale })` require it, and the
  queued job carries it beside the address. The recipient's `User.locale`
  decides; an invitation, read by somebody without an account, uses the
  language its sender chose (`Invitation.locale`), which accepting it copies to
  the new account. Who decides for which mail is in `docs/mail.md`.
- **Push notifications** (`push`) are built in the recipient's
  `User.locale` when the job is queued: the comment push in
  `comment-notifications.ts`, the calendar reminder in
  `apps/worker/src/calendar/reminder-message.ts`, times formatted with that
  locale. The free-text push of `exo_push_send` stays what the caller wrote.
- **The run diagnosis** (`diagnostics`) is stored as a key and its arguments
  on `ai_run` (`errorDetailKey`, `errorDetailArgs`) and rendered by
  `renderAiRunDiagnosis` in `packages/i18n/src/diagnosis.ts`: German into
  `errorDetail` by the worker, the requester's locale by the API, the
  viewer's by the panel. Numbers inside are ICU arguments, so they are
  grouped the reader's way.
- **A code the worker stores.** A failed render or project build keeps an
  English `errorCode`; `renderErrorKey` and `projectBuildErrorKey` in
  `packages/contracts` fold it into a closed list (`unknown` for anything
  newer), the browser renders that through `render.errors` and
  `projects.buildErrors`, and the API writes the response's `error` in the
  requester's language with `serverTranslator` (`readerLocale` in
  `apps/api/src/common/reader-locale.ts`). A socket event carries the code and
  never a sentence, because it has many readers. `server-codes.test.ts` in
  `packages/i18n` fails when a code has no German sentence.
- **Stored vocabulary is not interface text.** `ENTITY_TYPE_LABELS` and
  `ENTITY_PROPERTY_NAMES` are option and column names in the entity database,
  matched by name, and stay German in every locale; the browser shows a type
  through `entities.types`.
- **The feature registry.** Each entry's title, summary, paragraphs
  (`details.p1` onwards, the catalogue has no arrays) and `where` sit in the
  `features` namespace under the entry's id; `packages/features` keeps the
  facts. `GET /api/features` renders them in the requester's locale
  (`readerLocale`), so `/hilfe` and `exo_features` agree, and the namespace is
  kept out of the browser payload (`apps/web/src/i18n/namespaces.ts`).
  `scripts/check-feature-coverage.mjs` fails when an entry lacks its words or
  the catalogue has words for an id that is gone (`docs/features.md`).
- **Chat commands** (`commands`) answer in the language of whoever typed
  them: `executeCommand` in `apps/api/src/ai/conversations.service.ts` asks
  `readerLocale` and hands `runChatCommand` a `serverTranslator`. Tool
  descriptions in `/tools` stay the catalogue's model-facing text.
- **Codes the page words itself.** A formula or rollup problem is a
  `FormulaError` with a code from `FORMULA_ERROR_CODES` and its arguments;
  the API puts it into the error's `details.formula` (and the code into
  `details.reason` for agents), and the browser words it from
  `database.formulaErrors` (`formula-error.ts` in
  `apps/web/src/components/database`), the same for the syntax check while
  typing. An overview failure is stored as JSON in `DocumentDigest.lastError`
  and served as `errorDetail` (`document.overview.errors`; an older row's
  German sentence stays readable as `error`), a cover failure travels as
  `errorDetail` on `document.cover.generated` (`document.cover.generationErrors`),
  and a snapshot comparison sends `notices` and `nodeType`
  (`document.snapshotDiff.notices`, `.blockTypes`). The German `nodeLabel` and
  the notice sentences remain for the agent text of `exo_page_snapshot_diff`.
  `document-codes.test.ts` in `packages/i18n` fails when a code has no
  German sentence.
- **The editor's own node views.** `packages/editor` draws the file and PDF
  blocks, the text dialog, the breadcrumb, the table of contents, the toggle
  button and the embed frame itself, and knows no locale. It keeps the German
  in `GERMAN_EDITOR_WORDS` (`editor-words.ts`) and takes the reader's through
  `buildEditorExtensions({ words })`; `useEditorWords` in
  `apps/web/src/components/editor/editor-words.ts` builds them from
  `editor.nodeViews`. A new string in a node view is a field of `EditorWords`,
  which makes it a compile error in the hook until it has words.
- **Why an attachment's text could not be read** is `Attachment.textErrorCode`,
  one of `ATTACHMENT_TEXT_ERROR_CODES`, served as `errorCode` beside the English
  detail in `error` and worded from `editor.nodeViews.media.textErrors`. A row
  from before the codes has only the detail, which is then shown as it is.
- **Job progress** is a step code, never a label: `reportProgress(percent,
step)`, and the materialization's steps are `JOB_PROGRESS_STEPS`, worded
  from `shell.jobProgress.steps`. The other queues report English codes nobody
  is shown.
- **A skipped overview refresh** answers with a code in `reason`
  (`OVERVIEW_SKIP_REASONS`); `exo_page_overview_refresh` words it for agents.

## Correcting a translation by hand

Edit the target file. The tool notices the text is no longer what it wrote
and stops touching it. When the German of that key changes later, the tool
reports it instead of overwriting it, and the gate is red until one of:

- you correct the translation and confirm it:
  `pnpm i18n:translate --accept pl:settings.language.intro`
- you let the tool redo it: `pnpm i18n:translate --locale pl --overwrite-manual settings.language.intro`

## A new language

1. Add the tag to `SUPPORTED_LOCALES` and its endonym to `LOCALE_ENDONYMS`
   in `packages/contracts/src/locale.ts`.
2. Add its register to `packages/i18n/glossary.json` and, where the glossary
   has terms, the translation of each.
3. Add its English name to `LANGUAGE_NAMES` in `scripts/i18n/translate.mjs`.
4. `pnpm i18n:translate --locale <tag>`.

Nothing else changes: the settings page lists the new language, negotiation
finds it, the gate checks it.

## Formatting and sorting

Dates, numbers and relative times come from `useFormatter()` in the browser
and `createFormatter` from `use-intl/core` on the server, both with the
active locale. A new `'de-DE'` in a formatter is a defect.

The week starts where the locale starts it: `firstDayOfWeek` in
`apps/web/src/components/database/calendar/range.ts` reads the locale's week
data (Sunday for `en` and `pt-BR`, Monday for the others), and the week
window, the month grid and the weekday header all ask it. The date picker
gets the same answer from its react-day-picker locale.

Order that a person reads alphabetically (titles in a list) uses
`Intl.Collator(locale)`. Order that is technical (`orderKey`, ISO timestamps,
ids, slugs, anything hashed or serialised) compares by code unit and never
calls `localeCompare`, which silently depends on the process's locale.

## How the ratchet counts

`scripts/check-i18n-literals.mjs` reads `apps/web`, `packages/ui` and
`packages/editor` and counts every line of code, comments and route paths
removed, that carries German: an umlaut or ß, a word from its lists, or a word
with a German ending such as -ung, -keit, -lich or -ieren. It is a measure,
not a parser, so it misses German that has none of these, and it counts a
German identifier (a tab's value, a search keyword for an icon) that is not
interface text; the baseline carries those. When the measure itself changes,
the baseline is written anew: delete the file and run `--update`.

## What is not translated

User content of every kind, the model-facing text (system prompts, MCP tool
descriptions, `instructions.ts`), logs and error codes. The styleguide's demo
sentences under `/design-system` stay German; the components they show are
translated.

## The model

`scripts/i18n/translate.mjs` pins `google/gemini-3.8-flash`. It was chosen on
2026-09-25 against a sample of 51 interface strings (36 error messages, 10
labels and explanations, 5 ICU messages with plural, select, date and a
rich-text tag), translated into Polish and French by four candidates:

| Model                          | Result                                                                                                      |
| ------------------------------ | ----------------------------------------------------------------------------------------------------------- |
| `google/gemini-3.8-flash`      | all checks passed; every Polish plural category right, including `other`; gender-neutral phrasing; chosen   |
| `deepseek/deepseek-v4.1-flash` | all checks passed and cheapest; gendered forms where the reader is unknown ("Otrzymałeś")                   |
| `anthropic/claude-sonnet-5`    | all checks passed; Polish `other` in the `many` form, letter-style capitals ("Ci"); several times the price |
| `mistralai/mistral-large-2512` | rate-limited upstream, no result                                                                            |

The sample also changed the prompt: every model wrote French apostrophes as
`''` when told that ICU needs doubled apostrophes, so the tool now asks for
the typographic apostrophe (’), which needs no escaping. Changing the model is
a commit with a new sample, not an environment variable left set by accident;
`I18N_TRANSLATE_MODEL` exists for trying one.

The request asks for `reasoning: { effort: 'minimal' }`. A second sample on
2026-09-25 (40 strings from settings, ai and help, into English, French and
Polish, 120 translations) measured the effort and a second look at DeepSeek:

| Run                                | Cost   | Time  | Reasoning share | ICU problems |
| ---------------------------------- | ------ | ----- | --------------- | ------------ |
| `google/gemini-3.8-flash`, default | $0.093 | 124 s | 73 %            | 0            |
| `deepseek/deepseek-v4.1-flash`     | $0.054 | 306 s | 88 %            | 0            |
| `google/gemini-3.8-flash`, minimal | $0.031 | 41 s  | 0 %             | 0            |

Minimal effort differs from the catalogue about as often as a second default
run does, with wording variants rather than errors. DeepSeek stayed close to
the German sentence structure and broke established terms ("snapshot" where
the catalogue says "instantané" and "migawka").
